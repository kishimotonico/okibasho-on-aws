# コンセプト

## 目的

Claude Code、Codex などの AI エージェントや開発者が生成した HTML を、URL ひとつで簡単に共有するための小さな Web サービスを作る。

共有相手は社内メンバーに限定する。アップロードできるのも閲覧できるのも、認証済みの社内メンバーだけである。

主な用途:

- 分析結果や説明資料を HTML で共有する
- 簡単な UI モックを共有する
- 単一 HTML だけでなく、画像・CSS・JavaScript を含む複数ファイル構成も共有する
- ブラウザからドラッグ＆ドロップでアップロードする
- Claude Code / Codex などから CLI 経由でアップロードする
- 内容を差し替えながら、同じ URL で最新版を見せ続ける

## 規模感

社員数は約 30 名。アクセスは全ユーザー合計で 10〜100 request/hour 程度を想定する。高負荷・高可用性・極端な低レイテンシは求めない。

## 優先順位

1. シンプルなアーキテクチャ
2. セキュリティ境界が明確であること
3. 運用コストが低いこと
4. AI エージェントや開発者から容易に利用できること
5. AWS 上で IaC 管理できること

判断に迷ったら次を優先する。

- Simple > Feature rich
- 標準機能 > 独自実装
- ブラウザのセキュリティ境界 > アプリケーション側の回避策
- IAM に委譲できる認可 > アプリコードで書く認可

「サービスや構成要素を増やせばベストプラクティスになる」という判断はしない。対象は 30 人規模の小さな社内ツール。

ただしシンプルさを最優先するのはインフラアーキテクチャの話。アプリ層（web / CLI）の技術選定では安定感よりも、技術的なチャレンジとモダンな技術の積極的な採用を重視する。

## MVPでやること

- Google アカウントでのログイン（会社の Workspace ドメインのみ許可）
- HTML 単体アップロード
- ディレクトリアップロード
- Web の drag & drop アップロード
- CLI からのアップロード（ブラウザ連携のログイン付き）
- 共有 URL の発行。URL は `/p/<user>/<slug>/`。slug はユーザーが指定し、**ユーザー単位で一意**
- 同じ URL への再アップロード（内容の差し替え）。参照できるのは常に最新版
- 保存期間はデフォルト 30 日、操作で無期限に変更可能
- My Pages（自分のページ一覧）
- ページ削除

## MVPでやらないこと

- 管理者ロール、RBAC
- 他人のページ編集、owner 変更
- 組織・チーム、コメント、履歴の閲覧
- 過去バージョンの参照・切り戻し
- 社外向けの URL 共有（認証なしで誰でも見られる公開）
- analytics、全文検索、アクセスログ閲覧
- パスワードによる共有、共有相手の限定
- MCP server
- CI/CD からのアップロード統合
- URL の後からの変更（slug のリネーム）

## 将来の拡張候補

必要になった場合のみ検討する。

## 完成イメージ

Web:

1. 管理アプリを開いて Google ログイン
2. HTML またはディレクトリを drop
3. slug と保存期間（30 日 / 無期限）を選んで Upload
4. 表示された URL を共有

CLI:

```console
$ share-html login
Opening browser...
Authenticated.

$ share-html ./report/ --name q3-report
Uploading 4 files...

https://pages.share.example.jp/p/tanaka/q3-report/

$ share-html ./report/ --name q3-report --permanent
Uploading 4 files...

https://pages.share.example.jp/p/tanaka/q3-report/
```

閲覧者が URL を開くと、未認証なら Google ログインを挟んで HTML が表示される。独自ドメイン導入前は閲覧認証なしで検証する。

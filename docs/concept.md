# コンセプト

## 目的

Claude Code、Codex などのAIエージェントや開発者が生成したHTMLを、社内メンバーへ簡単に共有するための小さなWebサービスを作る。

主な用途:

- 分析結果や説明資料をHTMLで共有する
- 簡単なUIモックを共有する
- 単一HTMLだけでなく、画像・CSS・JavaScriptを含む複数ファイル構成も共有する
- ブラウザからドラッグ＆ドロップでアップロードする
- Claude Code / Codex などからCLI経由でアップロードする

## 規模感

社員数は約30名。アクセスは全ユーザー合計で10〜100 request/hour程度を想定する。高負荷・高可用性・極端な低レイテンシは求めない。

## 優先順位

1. シンプルなアーキテクチャ
2. セキュリティ境界が明確であること
3. 運用コストが低いこと
4. AIエージェントや開発者から容易に利用できること
5. AWS上でIaC管理できること

判断に迷ったら次を優先する。

- Simple > Feature rich
- 標準機能 > 独自実装
- ブラウザのセキュリティ境界 > アプリケーション側の回避策

「サービスや構成要素を増やせばベストプラクティスになる」という判断はしない。対象は30人規模の小さな社内ツール。

ただしシンプルさを最優先するのはインフラアーキテクチャの話。アプリ層（web / CLI）の技術選定では安定感よりも、技術的なチャレンジとモダンな技術の積極的な採用を重視する。

## MVPでやること

- Googleアカウントでのログイン（会社のWorkspaceドメインのみ許可）
- HTML単体アップロード
- ディレクトリアップロード
- Webのdrag & dropアップロード
- CLIからのアップロード（ブラウザ連携のログイン付き）
- 共有URLの発行。アップロード時に読みやすい名前（slug）を指定できる（省略時はランダムID）
- 保存期間はデフォルト30日、操作で無期限に変更可能
- My Pages（自分のページ一覧）
- ページ削除
- 閲覧側も社内認証済みユーザーのみ

## MVPでやらないこと

- 管理者ロール、RBAC
- 他人のページ編集、owner変更
- 組織・チーム、コメント、version管理、履歴
- analytics、全文検索、アクセスログ閲覧
- MCP server
- CI/CDからのアップロード統合
- 社外公開、パスワード共有
- slugの後からの変更（名前を変えたければ再アップロードする）

## 将来の拡張候補

必要になった場合のみ検討する。

- MCP（CLI/APIのwrapperとして追加できる想定）
- GitHub Actionsからのアップロード
- ページのtitle・description、検索
- 共有先の限定（shared-with）
- 期限延長、カスタム保存期間
- owner移譲、管理者ビュー
- ページのversioning
- 可変slug（CloudFront Function + KeyValueStoreのマッピング層で、データ移動なしに後付けできる）

## 完成イメージ

Web:

1. 管理アプリを開いてGoogleログイン
2. HTMLまたはディレクトリをdrop
3. 30日 / 無期限を選択してUpload
4. 表示されたURLを社内メンバーへ共有

CLI:

```console
$ share-html login
Opening browser...
Authenticated.

$ share-html ./report/
Uploading 4 files...

https://pages.share.example.jp/p/019c1292-.../
```

閲覧者はURLを開き、未認証ならGoogleログインを挟んでHTMLが表示される。

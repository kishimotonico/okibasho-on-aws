アップロードフォーム中央（`.composer` の中、案内文の上）に置く主役アイコンの実装仕様。React 実装エージェント向けのドラフト。

- 幾何とアニメーションの一次ソースは `docs/icon-ideas/tuner-open-box.html` の `build()` / `target()` / `proj()`（作業中のため**読むだけで編集しないこと**）。数値が食い違ったらチューナー側を正とする。

- 組み込み先は `packages/web/src/components/UploadPanel.tsx` の `.composer`、色トークンは `packages/web/src/styles/app.css`、トーン・ルールは `packages/web/DESIGN.md`。

| --- | --- | --- |
| `h` | 箱の高さ（底面の辺 = 1 基準） | 0.9 |
| `shade` | 側面の陰影の強さ | 0.45 |

## 1. 形の定義

### 1.1 投影式（等角投影）

底面の1辺を **1** とするローカル座標 `(x, y, z)`（`z` は高さ、上向き正）を、チューナーの `proj()`（`tuner-open-box.html#L200-202`）と同じ式で2D化する。

```
C30 = cos(30°) ≈ 0.866
S30 = sin(30°) = 0.5
proj(x, y, z) = ( (x - y) * C30,  (x + y) * S30 - z )
```

実装はチューナーと同じく座標系全体を `SC = 16`（底面の辺 = 16 viewBox 単位）でスケールする。これは見た目の比率（線の太さと形の大きさの関係）が今回チューナーで調整した見え方と一致させるための固定値なので、線幅（`wOut` などの数値）も含めてこのスケールのまま移植すること。辺を 1 に正規化して線幅だけ相対値に変換する、といった再設計はしない。

### 1.2 箱本体の頂点

底面の正方形の四隅を次のように置く（`T`=奥、`R`=右、`B`=手前、`L`=左。この命名はチューナーの変数名に合わせている）。

```
T = (-0.5, -0.5)   R = (0.5, -0.5)   B = (0.5, 0.5)   L = (-0.5, 0.5)
```

- **開口部（上面）の輪郭**: `T, R, B, L` を `z = h` で `proj` した4点を結んだ菱形（`top`）
- **底面**: 同じ `x, y` を `z = 0` で `proj` した4点（描画には `L0, B0, R0` のみ使用。奥側 `T0` は側面に隠れて見えないため描かない）
- **側面**: 見える2面のみ描く
  - `face-l`（左手前面）: `L(z=h) → B(z=h) → B(z=0) → L(z=0)` を結んだ四角形
  - `face-r`（右手前面）: `B(z=h) → R(z=h) → R(z=0) → B(z=0)` を結んだ四角形
  - `edge-mid`（最前面の縦稜線）: `B(z=h) → B(z=0)`
  - `outline`（外形シルエット）: `L(z=h) → L(z=0) → B(z=0) → R(z=0) → R(z=h)` の折れ線

### 1.3 フラップ

フラップは4枚だが、挙動は前後で対になっているので実質2種類のパラメータ（奥用 `bLen/bAng`、手前用 `fLen/fAng`）で4枚とも決まる。

| フラップ | ヒンジ辺（底面の辺、`z=h`） | 外向き法線 `n` | 使うパラメータ |
| --- | --- | --- | --- |
| `bl`（奥・左） | `T → L`（辺 `x = -0.5`） | `(-1, 0, 0)` | `bLen`, `bAng` |
| `br`（奥・右） | `T → R`（辺 `y = -0.5`） | `(0, -1, 0)` | `bLen`, `bAng` |
| `fl`（手前・左） | `L → B`（辺 `y = 0.5`） | `(0, 1, 0)` | `fLen`, `fAng` |
| `fr`（手前・右） | `B → R`（辺 `x = 0.5`） | `(1, 0, 0)` | `fLen`, `fAng` |

`bl`/`br` は奥の頂点 `T` に集まる2辺、`fl`/`fr` は手前の頂点 `B` に集まる2辺——これが「奥のフラップ」「手前のフラップ」という呼び方の根拠。

**角度の定義**（`angDeg`。`FLAPS` の外向き法線 `n` を使って `tuner-open-box.html#L218-224` の式そのまま）:

```
a = angDeg * π / 180
方向ベクトル d = ( -n.x * cos(a),  -n.y * cos(a),  sin(a) )
外側の2点 = ヒンジの2点 + d * len   （len は辺=1基準の長さ）
```

- `a = 0`: `d = -n`（内向き・水平）→ **内側に倒れて閉じる**
- `a = 90`: `d = (0,0,1)`（真上）→ **垂直に立つ**
- `a = 180`: `d = n`（外向き・水平）→ **水平に外へ開く**
- `a = 270`: `d = (0,0,-1)`（真下）→ **真下に垂れる**

閉じるアニメーション（`closed` 状態変数、0〜1）では `angDeg → 0` に、かつ長さ `len → 0.5` に同時に補間する（辺1の半分ずつ伸びて中央でぴったり合わさり、正方形の開口部を塞ぐ）。

**フラップの描画**（`flap()` 関数、`tuner-open-box.html#L256-264`）: 4点 `q0(ヒンジ1), q1(ヒンジ2), q2(外側2), q3(外側1)` の四角形を

- 塗り1枚（`stroke: none`、色は通常 `--paper`。`closed > 0.6` かつ蓋の成功演出が有効なときだけ `--accent-soft` にミックス）
- 輪郭を4辺に分けて別々の太さで重ね描き:
  - `q1→q2`（側辺）: `wOut`
  - `q2→q3`（外側＝フラップ先端の辺）: `wOut` から `wIn` へ、`closed` で補間（開いている間はシルエットの一部＝太い、閉じるにつれ内側の折り目＝細くなる）
  - `q3→q0`（側辺）: `wOut`
  - `q0→q1`（ヒンジの辺＝箱の開口部の辺と重なる）: `wIn`（元から箱側の内側稜線なので細い）

### 1.4 紙（アップロードされるもの）

- 大きさ: 1辺 `sSize`（辺=1基準）の正方形を `z = h + sheetZ` の高さで `proj`。`sheetZ` はアニメーション変数（idle では `sFloat`）
- 色: 塗り `--accent-soft`、線 `--accent`、太さ `wSheet`
- `sLines` が on のとき、中に短い斜めの2本線（ドキュメントの罫線のような装飾）を追加。線幅は `wSheet * 0.8`

### 1.5 床の円い置き場所（`ring`。今回の決定版で有効）

- 楕円の半径: `rx = √2 * C30 * rR`, `ry = √2 * S30 * rR`（辺=1基準、中心は箱の底面中心＝原点）。`rR = 1.0` は「箱の底面の角に接する半径 0.71」より一回り大きく、箱の足元からはみ出して見える
- 線の太さ `wRing`（今回 2 — 箱本体の外形線 `wOut=1.5` より太い、最も強い線）
- 色: 通常時 `--line`、`drag`/`uploading`/`success` で `--accent` 側に遷移（`ringT`）。`rFill` が on のとき `success` でのみ `--accent-soft` を塗る（`ringFill`）

### 1.6 描画順（奥行きソート。固定 9 段階ではない）

現行の `build()`（`tuner-open-box.html` 内、232〜325行）は要素を固定順に並べていない。各要素に奥行き `d` を持たせて `items.sort((a, b) => a.d - b.d)` で昇順（`d` が大きい＝手前ほど後で描く）に並べ替える。`d` の決め方は要素の種類ごとに違う。

- **床の円（`ring`）**: `items` とは別枠で常に最初（文字列として先頭に連結）
- **開口部（`inner`）**: `d = -0.45` 固定
- **紙（`sheet`）**: `d = -0.44` 固定（表示中のみ push）
- **側面**（見える2面のみ）: `d` = その面の4頂点（回転後の3D座標）の `x + y` の平均（`depthOf`）
- **フラップ**（常に4枚とも push）: 同じ `depthOf` に、`br`/`fl`（y 方向の対）だけ `+1.0 * closed` を加算する。これにより `bl`/`fr`（x 方向の対）が先に倒れ、`br`/`fl` がその上に重なって中央に一本だけ合わせ目ができる
- **蓋のアクセント輪郭（`lid`）**: `d = 9` 固定（`lidOp > 0.01` のときだけ追加、常に最後尾）

side の可視判定と線幅、陰影も回転を反映して毎フレーム計算し直す。

- **可視判定**: 側面の外向き法線 `n` を箱の回転（`spin`）ごと回転させ、`n.x + n.y > 0` のときだけその面を描く（法線がカメラ方向を向いている面だけ見える）
- **縦の稜線の太さ**: 側面は上辺・下辺を `wOut` で、左右2本の縦の稜線は「隣の面も見えていれば `wIn`（内側の稜線）、見えていなければ `wOut`（外形）」で描き分ける
- **側面の暗さ**: 法線が右（x軸）を向くほど暗い。`t = 0.22 + 0.16 * clamp01((n.x - n.y + 1) / 2)`、`fill = color-mix(in srgb, var(--paper) X%, var(--ink))`（`X = 100 - shade * t * 100`）
- **フラップが閉じるときの長さ**: `fLen`/`bLen` の決定値から実物どおり `0.5` まで `closed` で `lerp`（辺1の半分ずつ伸びて中央でぴったり合う）
- **フラップの先端（遠い辺）の線幅**: `wOut → wIn` へ `closed` で `lerp`（開いている間は外形として太く、閉じるにつれ内側の折り目として細くなる）
- **閉じた面の塗り**: `closed > 0.5` のとき `lidOp` で `--paper → --accent-soft` へ色をミックスした `lidFill` を使う（`closed <= 0.5` の間は `--paper` のまま）

### 1.7 線の太さの階層

| 用途 | 変数 | 決定値 | 備考 |
| --- | --- | --- | --- |
| 外形（箱・フラップのシルエット） | `wOut` | 1.5 | 側面の `outline`、フラップの側辺2本 |
| 内側の稜線（折り目・最前面の縦線・開口部） | `wIn` | 1.2 | `wOut` との比は 1.25:1 とやや控えめな階層（チューナー既定の 2.0:1.3 ≒ 1.5:1 より差が小さい） |
| 紙 | `wSheet` | 1.8 | 箱の外形線より太い。紙は常にアクセント色で塗るので「置くもの」を最も強く見せる意図 |
| 床の円 | `wRing` | 2 | 全体で最も太い線。土台として画面を締める |

### 1.8 色トークン対応

チューナーは独自の CSS 変数（`--paper` / `--ink` / `--accent` / `--accent-soft` / `--line`）で色を参照している（`tuner-open-box.html#L237-240`, `#L249-251`）。`packages/web/src/styles/app.css` への対応は次の通り。

| チューナー | app.css | 備考 |
| --- | --- | --- |
| `--ink` | `--text` | 本文色。SVG の `stroke="currentColor"` はこの色になる想定（`color: var(--text)` を icon に指定） |
| `--accent` | `--emerald` | 紙・成功時の蓋・drag/uploading/success の床の円 |
| `--paper` | `--well` | フラップ・紙の下地。`.composer` の背景と同じ白 |
| `--line` | `--line` | 床の円の通常時のストローク（名前も同じ） |
| `--accent-soft` | **未定義。新規追加が必要** | 紙の塗り、閉じた蓋の塗り、成功時の床の円の塗り |

`--accent-soft` 相当は `app.css` に追加するのが最も簡単（例: `--emerald-soft: color-mix(in srgb, var(--emerald) 14%, var(--well));`）。DESIGN.md の「エメラルドはコピー成功の瞬間だけ」というルール（The Emerald-Only Rule）との整合は、このアイコン自体が「アップロード成功」の文脈でのみエメラルドを使う（紙 = これからアップロードされるもの、成功時の蓋・床 = アップロード成功の結果）ため矛盾しないはずだが、DESIGN.md 側にこのアイコンの使用を追記するかは実装エージェント・デザイン担当者間で確認してほしい（後述の申し送り事項）。

`inner`（開口部の暗さ）や `face-l`/`face-r`（側面の陰影）は `color-mix(in srgb, var(--paper) X%, var(--ink))` の形でチューナー側に定義されている。移植時は `--paper`→`--well`、`--ink`→`--text` に置換するだけで、比率（`shade * 0.22`, `shade * 0.38`, `0.25 + inner * 0.45`）は決定値（`shade=0.45`, `inner=0.45`）のままチューナーの式を丸ごと使ってよい。

`error` 状態の色は DESIGN.md 既存の `--danger` / `--danger-soft` を使う（後述 2.6）。

## 2. 状態と動き

土台となる状態遷移の考え方はチューナーの `target()`（`tuner-open-box.html` 内、350〜371行）と `render()`（439〜454行）の組み合わせそのもの。`target(p, state, t)` が `IDLE(p)` を基準に状態ごとの目標値 `g` を計算し、`render()` がそれを実際の値 `cur` へ収束させる。収束のさせ方は変数と状態によって2通りある。

- `uploading`／`success`、および `hover` の `sheetZ` は、毎フレーム目標値 `g[key]` をそのまま `cur[key]` に代入する（経過時間 `t` に応じて連続的に変化する動き——落下ループや一度きりのシーケンス——をそのまま反映するため）
- それ以外の状態・変数（`idle`/`hover`（`sheetZ` 以外）/`drag` など）は `k = 1 - 0.001^(16/260)` を使ったフレームごとの指数補間 `cur[key] = lerp(cur[key], g[key], k)` で目標値に近づける（約 0.26 秒で収束）

`UploadPanel` の `phase`（`'idle' | 'uploading' | 'success' | 'error'`）と `isDragging` から、アイコンに渡す実効状態は次のように導出する想定:

```
effective =
  phase === 'uploading' ? 'uploading' :
  phase === 'success'   ? 'success'   :
  phase === 'error'     ? 'error'     :
  dragging              ? 'drag'      :
  internalHover         ? 'hover'     :
                           'idle'
```

`hover` はアイコン自身の `pointerenter`/`pointerleave` で内部状態として持つ想定（props には現れない。2枚目参照）。

### 2.1 idle

- `sheetZ = sFloat`（0.42、常に一定の高さで静止）, `sheetOp = 1`
- フラップは決定値そのまま（`fAng=210`, `bAng=145`）、`closed = 0`
- 床の円: `--line` の細い（といっても `wRing=2` で最太）輪郭、塗りなし
- 動きなし（静止画）

### 2.2 hover

- 紙だけがゆっくり浮遊: `sheetZ = sFloat + bobAmp * sin(t / 300ms)`（振幅 `bobAmp` = 0.1、周期 約1.9秒。0.04 では目立たなかったため 0.1 に上げた）
- 奥のフラップが心持ち締まる: `dBack = -3`（`bAng` に加算 = 142°、わずかに垂直側へ戻る）
- 床の円・手前フラップ・開口部は idle のまま

### 2.3 drag over（`isDragging === true`）

- 紙が大きく沈む: `sheetZ = 0.06`（ほぼ開口部の高さまで下がり、「今にも落ちる」を示す）
- 手前のフラップが開く方向へ: `dFront = +6`（`fAng` に加算 = 216°、より外へ倒れる＝受け入れる仕草）
- 奥のフラップは締まる: `dBack = -8`（`bAng` に加算 = 137°）
- 床の円が色づく: `ringT = 1`（`--line → --accent` へ遷移）。塗りはまだなし
- 遷移は約 0.26 秒のイージング（他の値と同じ収束速度）

### 2.4 uploading（`phase === 'uploading'`）

`hover`/`drag` と違い、`t` に対して周期ループさせる（1周 `upMs`、既定 1200ms）。現行チューナーに実装済みで、以下は `target()` の `uploading` 分岐そのもの。

- 紙の落下ループ: `ph = (t / upMs) % 1` として
  - `sheetZ`: `sFloat` から `-0.6 * h` へ `ease(ph / 0.7)` で落下（`ph` が 0→0.7 の間に落ちきる）
  - `sheetOp`: `ph < 0.7` は不透明、`0.7〜1.0` の間に 1→0 へフェードアウト（消えて次のループの紙に切り替わる）
- フラップはわずかに揺れながら開いたまま: `dFront = 4 + 2 * sin(t / 180)`、`dBack = -6 + 2 * sin(t / 220)`
- 床の円は `success` と視覚的に区別できるよう、破線にして回し続ける
  - `ringT = 1`（`--accent` 色）
  - `ringDash = 1` → 破線化。円周を `rDash * 2`（既定 12 なので 24）分割した長さを `stroke-dasharray` の弧・隙間に使う（弧 `rDash` 本・隙間 `rDash` 本）
  - `dashOff = (t / 1600) % 1` として `stroke-dashoffset = -dashOff * 円周` を毎フレーム更新し、円周ぶんずつ流れているように見せる
  - 塗り（`ringFill`）はしない（`success` との違い）

### 2.5 success（`phase === 'success'`）

`t` を経過時間（ms→秒 `u`）として一直線に進む一回限りのシーケンス（ループしない）。

- `u: 0 → 0.45` — 紙が最後にもう一段落下: `sheetZ: sFloat → -0.6h`（`ease(u/0.45)`）
- `u: 0.4 → 0.65` — 紙がフェードアウト: `sheetOp: 1 → 0`
- `u: 0.35 → 0.9` — フラップが閉じる: `closed: 0 → 1`（`ease`）。フラップの長さが 0.5 まで伸びて中央で合わさり、開口部を完全に塞ぐ
- `u: 0.85 → 1.2` — 蓋がアクセント化: `lidOp: 0 → 1`（`closed > 0.6` の間、フラップ自体の塗りも `--paper → --accent-soft` にミックスされ、加えて開口部と同じ形の蓋アウトラインが `--accent` でなぞられる＝**蓋が薄い緑になる**、の実体）
- `u: 0.6 → 1.0` — 床の円が塗りつぶされる: `ringFill: 0 → 1`（`rFill=1` のため）。`ringT = 1` は维持（線は `--accent` のまま、回転・破線は止めて実線に戻す）
- 全シーケンスの目安時間は 1.2 秒程度（`u=1.2` 相当）。完了後は最終フレーム（閉じた箱＋緑の蓋＋塗りつぶされた床の円）で静止し続ける（ループしない）

「uploading と見分けがつく」の実体はこの2つ: **uploading = 紙が落ちては消えるループ＋床の円が破線で回転**、**success = 紙が最後に落ちて消え、フラップが閉じて蓋が薄緑になり、床の円が実線に戻って塗りつぶされる**（一度きりで静止）。

### 2.6 error（`phase === 'error'`。チューナー未定義・今回の提案）

チューナーにはこの状態が無いため設計を提案する。DESIGN.md の色ルール上、新しいアクセント色は増やさず既存の `--danger` / `--danger-soft` を使う。

- 直前の状態（多くは `uploading` の途中）から**中断して idle 形状へ戻る**: フラップ・紙・床の円をすべて `IDLE(p)` の目標値へ通常の収束速度で戻す
- それに重ねて短い「シェイク」を1回だけ再生: アイコン全体を `translateX` で ±3px, 3往復, 合計 300ms 程度（`transform-origin` は変えない。isometric な形自体は歪ませない）
- 同時に外形線（`outline` と床の円）の色を一瞬だけ `--danger` にフラッシュしてから `--text` / `--line` へフェードバック（300〜400ms）。紙・蓋はアクセント化させない（成功と混同しないため）
- `.composer` 側には既存の `message--error` テキストが別途出るので、アイコン側の演出は控えめ（長時間の点滅や色の常時変更はしない）に留める

### 2.7 クリック時の一回転

「置き場所」としての遊び心を出す delight interaction として、アイコン自体をクリックしたときに1回転させる。チューナーでは**画面平面上で回すコイン回転ではなく、本当のヨー回転**として実装されている——箱・フラップ・紙のすべての3D座標（と側面法線）に回転角 `θ` を掛けてから等角投影 `proj()` にかける（`build()` 冒頭の `rot()`）。

```
rot(x, y, z) = (x cosθ - y sinθ,  x sinθ + y cosθ,  z)
```

- `θ` はクリックした瞬間からの経過時間 `t` に対し `spinMs`（既定 900ms）で `0° → 360°` へ進む。イージングは `easeInOut`（cubic in-out: `t<0.5` で `4t³`、それ以降 `1 - (-2t+2)³/2`）
- 回転中も 1.6 節の可視判定（回転後の法線で `n.x + n.y > 0`）と奥行きソートがそのまま働くため、側面のどちらが見えているか・縦の稜線がどちらの太さか・側面の暗さが回転角に応じて動的に切り替わる。箱の見た目を固定してアイコンごと画面上で回すのではなく、実際に3D空間で箱を回して毎フレーム再投影している点が「コイン回転」との違い
- **床の円（`ring`）は回転しない**——`ring` は `rot()` を通さず常に真上から見た固定形状のまま描く
- **紙は回さない**——紙の頂点は `rot()` を通さず `proj` で直接投影する（箱だけが回り、紙は浮いたまま。紙まで回すと違和感があったため）
- トリガー: アイコン（`#hero`）のクリック。チューナーでは `state`（idle/hover/drag/uploading/success）に関係なく常に発火する
- 多重クリック: 再生中に再度クリックすると `spinT0`（回転開始時刻）が現在時刻にリセットされ、回転は `0°` からやり直しになる（角度は蓄積されない）
- React 実装での `effective` が `idle`/`hover` のときのみ有効にする制限や、`prefers-reduced-motion: reduce` での無効化（2.8）は、チューナー自体には実装されていない。UI 上の使い勝手として実装エージェント側で追加してよい

### 2.8 `prefers-reduced-motion` 対応

- `hover` の浮遊、`uploading` のループ、`success` の蓋クローズ、`drag` の遷移は全てクロスフェード無しの**即時切り替え**（`transition: none` 相当）にする。最終形（各状態の目標値）はそのまま見せてよく、動きだけを削る
- `uploading` の床の円の回転・破線は静止した実線＋`--accent` 色のみに簡略化（「今アップロード中」であることは分かるが、回転はしない）
- 2.7 のクリック回転は完全に無効化する

## 3. 実装方針の提案

### 3.1 コンポーネント

```ts
interface UploadBoxIconProps {
  phase: 'idle' | 'uploading' | 'success' | 'error';
  dragging: boolean;
  size: number; // px
}
```

`hover` はコンポーネント内部の `pointerenter`/`pointerleave` state として持ち、props には出さない（2章冒頭の `effective` 導出を参照）。

### 3.2 SVG 生成 vs CSS transform

| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **A. 毎フレーム SVG 再生成**（チューナー方式） | `proj()`/`build()` をそのまま移植し、`requestAnimationFrame` で `cur` 状態を補間しながら `path` の `d` 属性を毎フレーム再計算 | チューナーの見た目を最も忠実に再現できる。フラップの角度変化・紙の落下など「幾何が変わる」動きを正確に表現できる | React では `dangerouslySetInnerHTML` かノード直接操作が必要になりがちで宣言的でない。CPU コストがやや高い（今回の要素数なら問題にならない規模） |
| **B. 固定 path + CSS transform** | 06-box-v2.mjs のように各状態の固定 `path` を書き、`transform: translate/rotate/scale` と `opacity`／CSS variables でアニメーションさせる | 宣言的で React と相性が良い。GPU 合成でパフォーマンスが良い | 今回のフラップの動き（角度が連続変化し、かつ `closed` で長さも変わる＝形そのものが変わる）は単純な `transform` では正確に表現できない。近似（`scaleY`/`rotate` の組み合わせ）で妥協するとチューナーで作り込んだ見え方から角度がズレる |

**推奨: A（毎フレーム SVG 再生成）をベースに、可能な部分だけ B を併用するハイブリッド。**

- 紙の `translateZ` 相当（`sheetZ`）、床の円の色・塗り、蓋のオーバーレイの `opacity` は CSS 変数 + `transition`/`animation` で十分表現できる（形そのものは変わらないため）
- フラップの角度・長さ変化（`closed` に依存する部分）と開口部の菱形サイズは、`build()` を移植した関数で `path d` を毎フレーム計算する
- 2.7 の「クリック時の一回転」は B 方式（外側の `<g>` や wrapper 要素に `transform: rotate()`）でよい。ジオメトリ自体は変えない

つまり: **状態遷移（フラップの開閉・紙の落下）は A、床の円の色替え・蓋のフェード・クリック回転は B**、という役割分担を推奨する。

### 3.3 rAF vs Web Animations API

- `uploading` のような**無限ループ**で経過時間 `t` に応じて `path d` を再計算し続ける部分は、`requestAnimationFrame` が素直（チューナーと同じ実装をほぼそのまま移植できる）。WAAPI は `d` 属性の補間を直接は扱えない（Chrome の `d` アニメーション拡張はあるが Safari 非対応、README にも既出の注意点）ため不採用
- `success` のような**一度きりのシーケンス**も同じ `render(now)` ループの中で `state='success'` に切り替えて経過時間で駆動すれば、`idle` に戻すタイミング（最終フレームで止める）を含めて一貫した実装にできる
- 逆に、**形が変わらない**部分（床の円の色フェード、蓋の `opacity`、2.7 のクリック回転）は CSS `transition`/`@keyframes` または WAAPI (`element.animate()`) に任せてよい。rAF ループの負荷を減らせる
- 実装の目安: 1つの内部 `useEffect` で `requestAnimationFrame` ループを1本持ち、`phase`/`dragging`/内部 `hover` の変化を見て目標状態を切り替える。ループ内で `path d` 文字列を作り、SVG の `<path>` へ直接 `d` を書き込む（React の re-render を毎フレーム起こさないよう、ref 経由での直接 DOM 更新を推奨。チューナーの `hero.innerHTML = svg` に近い形で良いが、React 内では `pathRef.current.setAttribute('d', ...)` の方が安全）

### 3.4 favicon 用の静的 SVG 書き出し

- favicon はブラウザのタブ側で描画されるため、**CSS カスタムプロパティ（`currentColor` 含む）や `color-mix()` に依存できない可能性がある**——実際に埋め込む前に対象ブラウザでの `color-mix()` サポートを確認し、確実性を優先するなら値を焼き込む
- `app.css` の `:root` は `color-scheme: light` 固定でダークモード分岐が無いため、ライトパレットの実色（`--text: #1a1d21`, `--emerald: #1f7a4d`, `--well: #ffffff`, `--line: #d3d6db`）を直接埋め込んだ静的 SVG を1枚生成すればよい（ダークモード分岐は不要）
- 生成方法: チューナーの `IDLE(P)` 状態で `build()`/`svgFor()` を1回呼んだ出力（チューナー画面の「SVG（現在の状態のフレーム）」エクスポート機能がそのまま使える）を、色だけ変数参照から実色に置換する
- 16px 時は床の円・紙の中の2本線など細部が潰れる可能性があるため、favicon 専用に `wOut`/`wRing` を心持ち太くする、または箱本体のみ（紙・床の円を省く）簡略版にすることも検討可（4章の受け入れ条件で確認）

## 4. 受け入れ条件

### 4.1 サイズ別の見え方

| サイズ | 確認内容 |
| --- | --- |
| 96px | `.composer` 中央で主役として違和感がないか。フラップの前後非対称な開き方（奥は立ち上がり、手前は垂れる）が視認できるか |
| 48px | 開口部・フラップ・紙・床の円のすべての要素が識別できるか（重なって潰れる部分がないか） |
| 24px | 箱のシルエットと紙の位置関係が読めるか。床の円が過度に主張していないか |
| 16px（favicon 相当） | 箱の輪郭として認識できるか。最低限「開いた箱」と分かればよい（紙・床の円の細部は潰れても許容） |

### 4.2 状態ごとの確認方法

各状態を `packages/web` のブラウザ上（もしくは Storybook 等があればそこ）で個別に発火させ、目視確認する。

| 状態 | 発火方法 | 確認ポイント |
| --- | --- | --- |
| idle | 初期表示 | 静止していること。フラップの角度が決定値（`fAng=210`, `bAng=145`）通りに見えること |
| hover | アイコンにマウスオーバー | 紙がゆっくり浮遊し、奥フラップがわずかに締まること。ループが滑らかで途切れないこと |
| drag over | `.composer` へファイルをドラッグして重ねる（`isDragging=true`） | 紙が沈み、手前フラップが開き、床の円が緑に変わること。ドラッグを外すと idle に戻ること |
| uploading | 実際にアップロードを実行（もしくは `phase` を一時的に固定してテスト） | 紙が落ちては消えるループが繰り返されること。床の円が**破線で回転**しており、success と見分けがつくこと |
| success | アップロード成功後 | 紙が消え、フラップが閉じ、蓋が薄い緑に染まり、床の円が実線に戻って塗りつぶされ、そこで静止すること。ループしないこと |
| error | アップロード失敗（例: ネットワーク遮断や既存 slug 拒否で `window.confirm` を否とする以外の失敗経路） | idle 形状に戻りつつ、短いシェイクと `--danger` の一瞬のフラッシュが1回だけ再生されること。長時間点滅しないこと |
| クリック回転 | idle/hover 中にアイコンをクリック | 360° 回転して元の見た目に戻ること。アップロード操作（ファイル選択・ドラッグ）に干渉しないこと。`prefers-reduced-motion: reduce` 環境では回転しないこと |

### 4.3 その他

- OS/ブラウザの「動きを減らす」設定を有効にした状態で、idle/success 等の最終形が正しく表示され、ループ系の動きだけが止まっていることを確認する
- favicon として書き出した静的 SVG を実際にブラウザタブに表示し、`app.css` のトークンを一切参照せず単体で正しい色で表示されることを確認する

## 実装エージェントへの申し送り事項

1. `--accent-soft` に相当する app.css 側のトークンが存在しない。1.8 節で `--emerald-soft` の新規追加を提案したが、命名・追加場所（`app.css` か `UploadBoxIcon` 専用のスコープ付き変数か）は実装時に判断してほしい。またこのアイコンでの emerald 使用箇所（紙・成功時の蓋・成功時の床の円）が DESIGN.md の「The Emerald-Only Rule」の対象として書き足す必要があるかは、デザイン担当と要確認。
2. **`error` 状態はチューナーに一切存在しない**（5状態は idle/hover/drag/uploading/success のみ）。2.6 の内容は README・DESIGN.md のトーン（控えめ、危険色は `--danger` 限定）から今回作成した提案であり、実装前に決定者（チューナーを編集している方）に確認を推奨する。
3. `sheetOp`（紙の透明度）や `ringFill`、`ringDash` の切り替わりなどはチューナー内で `t` に対する区分的な線形補間（`0.4〜0.65` でフェードアウト、等）として確定している式だが、実際の秒数で見たときの「気持ちよさ」は実装後に実機（本物のアップロード所要時間やネットワーク遅延の中）で目合わせが必要になる可能性が高い。
